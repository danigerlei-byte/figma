DESIGN PRINCIPLES IN FIGMA 03
01

Visual hierarchy

Every screen has one most important thing — and the design makes it obvious in under a second.
WHY IT WORKS

People scan before they read. They land on the biggest, boldest, highest-contrast element first, then move down the levels you set. If two things shout equally, the eye stalls.

FIVE LEVERS
LEVERSTRONGERWEAKER
SizeLarger text and shapesSmaller
WeightBold, semiboldRegular, light
Color & contrastHigh contrast, accentGrey, low contrast
PositionTop, leftBottom, right
SpaceIsolated by whitespaceCrowded among others
IN FIGMA
Define a type scale as text styles (Display, H1, H2, Body, Caption) so every level is deliberate.
Use one primary button per screen; secondary actions become outline or text buttons.
Squint test: zoom to 25% and see what still stands out — that's your real level one.
Grayscale check: overlay a black frame with Color blend mode. If hierarchy vanishes, it relied on color alone.
AVOID Three or more competing hero elements • color as the only signal • font sizes that differ by just 1–2 px.

02

Alignment & grids

Every element lines up with something else. Invisible lines create order — and order reads as quality.
WHY IT WORKS

Aligned edges let the eye travel in straight paths. A layout that's 3 px off feels "wrong" even when people can't say why.

GRID STARTERS
DEVICECOLUMNSMARGINS / GUTTERS
Desktop1224 px
Tablet816–24 px
Mobile416 px
IN FIGMA
Add a layout grid to every top-level frame and save it as a grid style so all screens share it.
Use Auto layout Shift A for anything that stacks: buttons, cards, lists, nav bars.
Set constraints or Fill / Hug sizing so elements behave when frames resize.
Hold Alt while hovering to measure distances; Shift R shows rulers for guides.
Prefer one strong alignment edge (usually left) over mixing left, center and right.
AVOID Centered long body text • elements that almost align • nudging by eye instead of letting Auto layout handle spacing.
02 • ALIGNMENT & GRIDS 05
03

Spacing & proximity

Things that belong together sit close together. Space is how you group without drawing boxes.
WHY IT WORKS

This is the Gestalt law of proximity. The brain reads small gaps as "same group" and large gaps as "new section", so spacing alone can replace most dividers and borders.

8-POINT SCALE
TOKENVALUETYPICAL USE
space-14 pxIcon to its label
space-28 pxItems inside a small component
space-316 pxPadding inside cards and buttons
space-424 pxBetween related blocks
space-532 pxBetween groups
space-648–64 pxBetween page sections
IN FIGMA
Create the scale as number variables in a Spacing collection and bind them to Auto layout gap and padding.
Set nudge amount to 8 in Preferences so Shift + arrow moves in grid steps.
Keep space inside a group smaller than space around it — card padding 16, gap between cards 24.
AVOID Equal spacing everywhere • random values like 13 or 27 px • lines and boxes patching grouping that spacing should handle.
03 • SPACING & PROXIMITY 06
04

Contrast & color

A small palette applied by role looks more polished than many colors applied by mood.
WHY IT WORKS

When color is rare, it carries meaning — one accent instantly says "this is the action". Enough contrast makes the product readable for everyone, including people with low vision or in bright sunlight.

60-30-10 RULE • WCAG AA BASELINES
ELEMENTMINIMUM CONTRAST
Body text4.5 : 1
Large text (24 px+, or 18.5 px+ bold)3 : 1
Icons, input borders, focus rings3 : 1
IN FIGMA
Build color variables in two layers: primitives (blue-500) and semantic tokens (text/primary, action/primary). Design with semantic ones only.
Add Light and Dark modes to the semantic collection; switch a frame's mode to test dark theme in one click.
Check contrast with a plugin such as Stark or Contrast before handoff.
Reserve red, amber and green for status so they never compete with your accent.
AVOID Light grey text on white • more than one accent fighting for attention • meaning carried by color alone — add an icon or label.
04 • CONTRAST & COLOR 07
05

Typography

Most of an interface is text, so type does most of the design work. Few fonts, few sizes, set with care.
WHY IT WORKS

A consistent type scale creates hierarchy for free, and comfortable line length and line height make reading effortless.

TYPE SCALE (×1.25)
STYLESIZE / LINE HEIGHTWEIGHT
Display48 / 56 pxBold
H132 / 40 pxSemibold
H224 / 32 pxSemibold
H320 / 28 pxMedium
Body16 / 24 pxRegular
Small14 / 20 pxRegular
Caption12 / 16 pxMedium
IN FIGMA
One typeface is enough, two at most. Inter, Roboto, SF Pro are safe UI choices.
Save each row as a text style, named with slashes (Heading/H1, Body/Regular) so they group in Assets.
Body at 16 px, line height ~1.5×, 45–75 characters per line; headings tighter (1.2–1.3×).
Bind sizes to number variables with Desktop and Mobile modes for responsive type.
AVOID Five or more fonts • body text below 14 px • detached text that ignores styles • all-caps paragraphs.
05 • TYPOGRAPHY 08
06

Consistency & repetition

The same thing should always look and behave the same way. Repeat patterns until they become predictable.
WHY IT WORKS

Consistency lowers the effort of learning an interface — once people know what a button looks like, every new screen feels familiar. It makes your team faster too, because decisions are made once.

IN FIGMA
Turn any repeated element into a component Ctrl Alt K. Edit the main one and every instance updates.
Combine states and sizes into variants — Button: Primary/Secondary × Default/Hover/Disabled × S/M/L.
Use component properties (boolean, text, instance swap) so one component covers "with icon" and "without icon".
Publish styles, variables and components as a team library so every file shares one source.
Name layers clearly (Card/Product, Input/Text) so teammates and developers find them.
AVOID Detaching instances for quick fixes • three slightly different versions of the same card • colors and sizes typed by hand instead of taken from variables.
06 • CONSISTENCY & REPETITION 09
07

Balance & whitespace

Give every element room to breathe — and remove anything that doesn't help the user reach their goal.
WHY IT WORKS

Whitespace isn't empty space, it's focus. Fewer elements mean each gets more attention, and the design feels confident instead of crowded. Balance keeps the eye from drifting to one heavy corner.

IN FIGMA
Start each screen with: what is the one job here? Move everything else to a "parking lot" frame beside it.
Add more space than feels natural around headlines and key actions, then reduce only if it looks empty.
Check balance by toggling visibility Ctrl Shift H on heavy elements and watching the frame shift.
Use progressive disclosure: secondary options behind a "More" menu, tab or expandable section built as variants.
AVOID Filling every gap with content • decoration (shadows, gradients, icons) that carries no meaning • all the visual weight on one side.
07 • BALANCE & WHITESPACE 10
08

Feedback & affordance

What can be clicked should look clickable — and every action should get a visible response.
WHY IT WORKS

Affordance tells people what's possible before they try; feedback confirms what happened after. Without both, users hesitate, double-click, or give up.

REQUIRED STATES
STATEWHAT IT SHOWS
DefaultIt's available
HoverIt responds to the pointer (desktop)
PressedThe click registered
FocusKeyboard position, with a visible ring
DisabledNot available now, ideally with a reason
Loading • Success • ErrorThe result of the action
IN FIGMA
Build states as variants, wired with interactive components (While hovering → Hover, On click → Pressed).
Prototype the full flow, including empty, loading and error screens — not only the happy path.
Use Smart animate at 150–300 ms so transitions feel connected, not jumpy.
Touch targets at least 44 × 44 px on mobile, even when the icon is smaller.
AVOID Buttons that look like plain text • no focus state • forms that fail silently • designing only the screen where everything goes right.
